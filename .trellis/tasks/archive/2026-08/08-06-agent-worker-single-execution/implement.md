# 方案四：把单次执行从 AgentWorker 生命周期中独立 — 执行计划

## 前置

- 依赖方案三稳定（报告三→四顺序；三收缩 block_ops 后再拆单次执行，避免同时动两处热区）。
- 工作分支：`refactor/agent-worker-single-execution`。

## 实施顺序

1. **读当前代码**：核对 `worker.py` 的 `_process_request_locked`（含 379-1207、1295-1861）与 `core.py`、`conversation.py`、`context.py` 实际结构（报告行号已偏移）。
2. **盘点测试表面**：统计 4 个测试文件对 `_process_request_locked` 的 23 次直接调用，以及 `stream_chat`、模型获取、管理器、MCP、运行时全局入口替换点，作为改进基线。
3. **建立特征测试**：面向"单次执行结果"补七项行为测试（成功、审批挂起/恢复、部分结果、超时/取消、不可恢复异常、连接断开、收尾各执行一次）。
4. **提取单次执行深模块**：`AgentWorker` 只提交上下文并接收 `ExecutionResult`；内部由私有实现协作完成准备/执行/恢复/输出转换/失败挽救/历史提交/收尾。
5. **逐步替换测试**：把直接调用 `_process_request_locked` 的测试改为面向单次执行结果；减少全局入口替换。
6. **验证收尾唯一性**：确认历史提交、标题生成、追踪收尾各只执行一次。
7. **质量检查**：跑 worker 相关测试与全量 `pytest -q`。

## 验证命令

```bash
pytest -q tests/<worker_related_tests>
pytest -q   # 全量，确认无新增失败
```

## 评审门

- 代码评审：确认 `AgentWorker` 只负责队列/锁/生命周期；单次执行收敛到深模块；测试私有方法直调次数明显下降。
- 通过 `trellis-check` 复核，再合入 `dev`。

## 回滚点

- 风险高（报告标 L）。每个子步骤先建特征测试再移动实现。
- 若验收门不满足（测试反而更深耦合私有实现 / 单次执行仍混在队列生命周期），回退到该步合入前提交。

## 完成定义

- 单次执行收敛到深模块；`AgentWorker` 只负责队列/锁/生命周期。
- 测试直接调用 `_process_request_locked` 等私有方法次数明显下降；模块级获取函数替换数量减少。
- 历史提交/标题/追踪各执行一次。
- 全量 pytest 无新增失败。
