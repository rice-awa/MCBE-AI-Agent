# 方案一：收拢运行时 Harness 工具执行生命周期

## 目标

统一普通工具执行与审批恢复两条路径的幂等、工具审计、追踪和收尾规则，收敛到单一内部深模块。让两条路径只负责提供不同的起始状态，不再分别维护完整收尾流程。

## 范围

- `services/agent/harness/execution.py:943-1425`（普通执行）与 `execution.py:1633-1796`（审批恢复 `_resume_approved_block_plan`）。
- 相关测试：`tests/test_runtime_harness_execution.py`、`tests/test_block_ops.py`。

## 现状问题

`HarnessToolset.call_tool` 对外入口不复杂，但内部同时处理提出与追踪、方块预检与参数投影、规则判断与拒绝、审批挂起、幂等命中与写入、实际执行、异常分类与结果转换、工具审计、追踪收尾。审批恢复路径 `_resume_approved_block_plan` 又重新处理缓存读取、工具与计划匹配、幂等、执行、工具审计、追踪和结果转换，代码注释也说明它在"镜像主路径"。

风险不在于函数长，而在于**相同状态变化有两个实现位置**：以后调整工具审计字段、追踪状态、幂等规则或错误分类时，容易只改到其中一条路径。

## 验收标准

以下行为由同一实现驱动，且普通执行与恢复执行结果一致：

- [ ] 允许、拒绝、需要审批三种决策。
- [ ] 审批挂起后通过 `plan_id` 恢复。
- [ ] 重复调用的幂等命中。
- [ ] 参数投影失败、工具异常和 Addon 异常。
- [ ] 工具审计失败时主流程继续运行。
- [ ] 普通执行与恢复执行产生一致的追踪与结果状态。

## 必须保留的约束

- 方块工具必须先预检，再进入审批判断。
- `plan_id` 只用于恢复已冻结计划，不携带隐藏执行参数。
- 工具审计失败不得阻断 MCBE Chat Agent。
- 不改变 PydanticAI 工具调用接口和现有 mcbews v1 适配方式。
- 保留 PydanticAI 现有接入位置、现有工具接口和 Addon 适配方式。

## 删除检验（存在价值依据）

若删除统一执行流程，审批、幂等、工具审计和追踪逻辑会重新散回每个工具、恢复分支和 `AgentWorker`，因此该深模块能产生明确集中性与复用收益。

## 验收门 / 回滚门（报告 12.1）

- **验收**：普通执行与审批恢复的工具审计/追踪/幂等由同一实现驱动；两条路径测试通过。
- **回滚**：任一收尾规则存在第二份实现，或审计/追踪行为在两个路径不一致。
