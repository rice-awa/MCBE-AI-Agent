# 实施计划

## 阶段 1：冻结证据基线

1. 记录当前分支、提交、依赖版本和调研日期。
2. 汇总并去重子代理、Firecrawl、OpenAI 官方资料和 Context7 结果。
3. 对每条候选发现标注“已确认缺陷 / 设计风险 / 改进机会”和 P0/P1/P2。
4. 复核高风险源码行号与离线复现结果，排除测试专用路径和旧兼容路径造成的误判。

完成条件：至少 25 个有效外部来源；核心代码发现均有证据类型和当前行号。

## 阶段 2：形成审查报告

1. 写现代 Agent 提示词分层、工具声明和工具调用循环综述。
2. 单列 XML 标签结论，说明作用、限制、跨模型差异和建议消融评测。
3. 写本项目完整数据流、提示词组合、工具目录/Harness、MCP、上下文和观测现状。
4. 写值得保留的设计、差距矩阵和详细发现。
5. 给出目标架构、分阶段路线图、依赖、验收指标、建议测试与开放问题。
6. 附完整来源目录、Firecrawl 复跑输入和本地复现输入。

完成条件：新增 `docs/review/mcbe-chat-agent-architecture-prompt-review-20260815.md`，且不修改业务代码。

## 阶段 3：校验与收尾

1. 检查外部链接数量、域名和正文就近引用。
2. 自动检查所有仓库相对路径存在、引用行号不超过文件总行数。
3. 检查术语、严重级别、事实/推断标注和版本边界。
4. 运行 `git diff --check`，确认改动仅包含报告与当前 Trellis 任务文件。
5. 按 Trellis 流程记录检查结果并完成任务。

完成条件：所有 Acceptance Criteria 勾选，报告可独立阅读和复跑。

## 执行边界

当前任务处于 planning。完成调研汇总和规划摘要后，先取得用户明确批准，再运行 Trellis `task.py start` 并创建最终报告。
