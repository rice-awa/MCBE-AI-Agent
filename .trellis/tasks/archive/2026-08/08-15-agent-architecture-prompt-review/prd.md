# MCBE Chat Agent 架构与提示词审查

## Goal

产出一份以外部一手资料和仓库源码为证据的中文架构审查报告，解释现代 Agent 如何组织系统提示词、工具说明与工具调用协议，并评估本项目 MCBE Chat Agent 与这些实践之间的差距、风险和改进优先级。

用户价值：避免把“使用 XML 标签”误当成架构升级本身，明确哪些改进能真正提高工具选择、参数正确性、会话隔离、安全边界、可观察性和可评测性，为后续重构提供可执行依据。

## Background And Confirmed Facts

- 项目术语以 `CONTEXT.md` 为准，报告使用“MCBE Chat Agent”“运行时 Harness”“工具目录”“工具提示”等名称。
- 当前实现基于 PydanticAI，支持多个模型 provider、MCP、工具审批、工具审计、Trace、玩家级会话和提示词模板。
- 同一 Minecraft WebSocket 连接可服务多名玩家；审查必须覆盖 `sender` / `player_name` 的显式传递和隔离。
- 用户指定采用 Firecrawl 深度调研的“彻底档”，并允许使用子代理；所有子代理使用 `gpt-5.6-luna`、`max`。
- 最终交付物是 `docs/` 下的一份纯文字 Markdown 报告；本任务不修改业务实现。

## Requirements

### R1. 外部调研

- 检索不少于 10 个问题角度、使用不少于 25 个有效来源。
- 优先采用官方文档、公开源码、协议规范和论文；博客或二手资料仅用于补充观点。
- 至少覆盖：Codex CLI / OpenAI Agents 与 Responses API、Claude Code / Anthropic 工具使用、PydanticAI、MCP，以及至少一种图式或工作流 Agent 方案。
- 调研系统/开发者提示词的分层、XML/Markdown/结构化分隔的真实作用、工具 schema/说明、原生 function/tool calling、MCP、工具执行循环、审批与安全、上下文管理、错误返回、可观察性和评测。
- 清楚区分：模型原生协议、Agent 框架封装、应用提示词约定；不得把 XML 标签描述成工具调用协议。

### R2. 仓库架构审查

- 追踪玩家消息从 Gateway、MessageBroker、AgentWorker、Agent 运行时、工具执行到响应下行的完整路径。
- 审查提示词来源、组合顺序、模板变量、动态工具提示、provider/model 差异和会话上下文注入。
- 审查工具目录、PydanticAI 工具注册、MCP 接入、参数 schema、返回值、重试/超时/取消、审批、幂等、审计和 Trace。
- 审查测试是否覆盖关键 Agent 行为，尤其是多人隔离、工具选择/参数、错误反馈、审批恢复和上下文增长。
- 所有重要结论尽量给出仓库 `file:line` 证据；区分已确认缺陷、设计风险和改进机会。

### R3. 对比与建议

- 给出当前实现与现代实践的逐项对照，不以“是否用了 XML”作为单一评价标准。
- 形成按 P0/P1/P2 或等价等级排序的改进路线图，说明收益、成本、依赖、风险和建议验证方式。
- 提供目标提示词分层与工具调用架构的文字版参考设计；可给短小示例，但不直接改代码。
- 明确值得保留的现有设计，避免为了追赶框架形式而重写已经合理的部分。

### R4. 报告质量

- 报告包含执行摘要、范围与方法、现代实践、现状架构、差距矩阵、详细发现、目标架构、分阶段路线图、风险/反方观点、开放问题和完整来源。
- 外部事实使用可点击来源链接；仓库结论使用相对路径和行号。
- 标注调研日期、来源边界与推断；不得泄露密钥、本地配置或日志正文。

## Acceptance Criteria

- [x] `docs/` 下存在一份新的中文 Markdown 架构审查报告。
- [x] 报告引用至少 25 个有效外部来源，且核心主张优先由一手来源支持。
- [x] 报告覆盖系统提示词、工具提示、工具 schema、调用协议、执行循环、安全/审批、上下文、可观察性和评测。
- [x] 报告完整描述本项目 MCBE Chat Agent 的现状数据流，并为关键判断提供 `file:line` 证据。
- [x] 报告明确回答“XML 标签是否必要、解决什么、不解决什么”。
- [x] 报告给出可执行的优先级路线图和建议验证指标，但不修改业务代码。
- [x] 报告经过链接/引用、路径/行号、术语一致性和 Markdown 结构检查。

## Out Of Scope

- 实际重构 Agent、提示词、工具目录或 provider 代码。
- 修改 Addon、协议或 SDK。
- 运行真实付费模型、Minecraft 世界或会产生外部副作用的工具调用。
- 对闭源 Agent 未公开的内部系统提示词作无依据推断。

## Technical Notes

- Codex CLI 相关事实必须用 OpenAI 官方文档或官方公开源码核验。
- PydanticAI 等库的当前 API 与语义通过 Context7 官方资料核验。
- `code-review` 技能面向固定分支差异，不适用于本次全仓现状架构审查；本任务按源码/契约审计执行。
- 调研与源码审查的收口证据记录在同任务目录 `research.md`；最终报告必须吸收五个子代理的独立结论，并由主代理对高风险项交叉核验。
- 已确认的最高优先级证据包括：生产工具结果过早字符串化导致失败被按成功收尾，以及 stdio MCP 显式继承完整父进程环境。
- PydanticAI 的项目版本是 1.94.0；当前 v2 文档只用于版本差异说明，不能直接当作项目 API。
