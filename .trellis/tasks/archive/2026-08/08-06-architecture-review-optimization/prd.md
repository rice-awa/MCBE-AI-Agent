# 架构优化：按 review 落实六项候选方案

## 目标

依据 `docs/review/architecture-review-20260806-191022.md` 审查结论，逐步落实六项架构优化候选方案及一项独立 bug 修复。目标是收拢已经存在、但分散在多条路径中的规则到少数深模块，改善测试表面，并巩固多人会话隔离这一核心安全不变量。

父任务只拥有**源需求、子任务映射、跨子任务验收标准与最终集成复核**，本身不承担具体实现。具体实现由各子任务独立计划、实施、检查与归档。

## 范围

- 六项候选方案对应的代码区域（见下方子任务映射）。
- 每项候选的验收指标与回滚门沿用报告 12.1 节。
- 玩家身份安全门（双玩家交错测试）作为方案二的前置交付。
- 独立 bug：CLI `info` 的模型上下文窗口展示（单独跟踪，不随架构重构提交）。

不在范围内的行为约束（所有子任务必须遵守，见报告第三节与各方案"必须保留的约束"）：
- 保持 mcbews v1 线协议不变。
- 出站长文本继续经过 `BrokerResponseBridge` 或 SDK 下行模块（`McbeOutboundDelivery` / `McbewsV1Delivery`）。
- 玩家身份只用 `event.sender` / 显式 `player_name`；按 `(connection_id, player_name)` 分桶。
- 大文件行数本身不是问题；不把大函数机械切碎，判断标准是接口是否更小、规则是否更集中、测试是否更接近调用方。
- 不为只有一个实现的依赖创建抽象接口。

## 验收标准

- 六个子任务均完成，且各自通过报告的验收指标（12.1 节）与回滚条件判定。
- 不存在"某项触发的测试绕过公开接口的次数不降反升"的候选。
- 最终集成复核确认：六项候选合并到 `dev` 后，玩家隔离不变量、mcbews v1 线协议、下行发送路径均保持完整。
- 既存测试失败（CLI context 展示）修复后全绿；该修复不混入任何架构重构提交。
- 基础测试基线（pytest）在每项重构落地后保持：除独立 bug 外无新增失败。
