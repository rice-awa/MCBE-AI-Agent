# MC Agent「操作方块」工具设计稿（仅设计理念，不含实现）

---

## 一、核心设计原则

本工具面向 Minecraft 环境，为 Agent 提供批量读取与编辑方块的能力。设计围绕以下原则展开：

1. **意图与执行分离，且意图必须可被精确校验**  
   工具接受的输入不仅描述“做什么”，还必须包含可验证的前置条件，使得 Agent 的预期行为在执行前就能被检查，避免歧义。

2. **输入健壮性与业务语义校验分层**  
   第一层负责格式归一化（如坐标格式、方块 ID 别名），第二层负责语义校验（坐标重叠、方块合法性等），二者职责清晰分离。

3. **精确匹配优先，宽松匹配兜底，且兜底必须显式标注**  
   优先按严格状态匹配，失败后允许在定义的“宽松模式”下再次匹配；一旦触发宽松匹配，必须在结果中明确告知调用方，不能静默降级。

4. **执行前强校验，拒绝有歧义的操作**  
   坐标重叠、前置条件不满足、方块 ID 非法等情况，必须在执行游戏动作前拦截，并给出具体的失败原因。

5. **最小化无效操作**  
   若目标坐标已经处于期望状态，直接判定为“无需变更”并上报，不发送多余的放置指令。

6. **操作原子性作为可选契约，默认允许部分成功**  
   区别于纯原子性，在 MC 场景下部分成功往往比整体回滚更有价值；工具应提供明确的原子性选项，由调用方按需选择。

7. **执行后必须确认，建立闭环验证**  
   由于 MC 世界的分布式与异步特性，发出指令后必须重新读取目标状态，与预期比较，确保操作真实生效。

8. **并发按坐标/区块做队列互斥**  
   针对同一坐标或区块的操作串行化排队，不同坐标/区块可并行；此机制仅保证自身发起的操作不冲突，不防止外部世界的变化。

9. **取消与超时管理需与锁状态协调**  
   超时或取消时，不能立即释放锁，必须等待明确的操作结果（成功/失败/未知）后再解锁，避免竞态。

10. **执行结果与预览共享同一套校验逻辑**  
    预览所展示的预期效果与实际执行时的判断逻辑必须一致，确保“所见即所得”。

11. **错误信息必须是结构化的、可操作的**  
    每种失败场景（匹配失败、重叠、状态不符、权限不足等）都携带清晰的上下文，方便 Agent 做出后续决策。

## 二、设计目标的根本差异

与确定性、本地、同步状态的文件操作不同，MC 世界是 **非确定性、分布式（客户端-服务端）、异步状态** 的。因此，本工具的核心挑战在于：**将“意图-校验-执行-确认-反馈”的骨架保留，但把每一环的“确定性假设”替换为 MC 场景下对应的不确定性应对机制**。特别地，状态在你读取与执行之间可能被其他玩家、生物、红石电路改变，因此“读后确认”是必要步骤，而非可选增强。

## 三、Schema 设计：意图描述层

- **批量操作**：一次工具调用可描述“在多个坐标放置/替换多种方块”，减少来回调用，让模型一次性表达完整意图。
- **每个编辑单元（Edit）** 包含：
  - **坐标**（世界坐标或相对坐标，需在 schema 中明确统一）。
  - **期望放置后的方块类型与状态**（如朝向、开关状态等）。
  - **前置断言（Precondition）**：可选地指定“当前该位置应为何种方块（含状态）”。该断言作为本次修改是否合法生效的锚点，地位等价于文本替换中的 `oldText` 必须唯一匹配。
- **覆盖模式声明**：调用方可显式指定“允许覆盖任意方块”或“仅当目标位置为空气/特定方块时允许放置”。这替代了纯文本匹配中“oldText 必须唯一”这种静态验证，因为 MC 里的合法性依赖于运行时状态。

---

## 四、参数健壮性 vs 语义校验的分层

### 4.1 健壮性层（格式归一化）
- 兼容模型可能给出的畸形表达：
  - 坐标写成字符串或数组形式。
  - 方块 ID 大小写不统一。
  - 使用别名而非规范 ID（如 `stone` → `minecraft:stone`）。
- 此层只做格式归一化，不做任何“能否执行”的判断。

### 4.2 语义校验层
- 检查：
  - 坐标是否重复。
  - 多个 Edit 是否指向同一坐标（即 MC 场景下的“重叠”）。
  - 方块 ID 是否在当前版本的合法方块表内。
  - 前置断言中引用的方块类型是否合法。
- 此层在所有游戏内动作执行前完成，全部通过才继续。

---

## 五、放置方块（写操作）的核心流程

流程分为 **执行前校验 → 空变更判定 → 执行 → 执行后确认** 四段：

1. **执行前校验（前置条件）**
   - 目标坐标当前方块状态是否满足 Edit 声明的前置断言。
   - 失败时生成结构化错误，而非笼统失败。

2. **空变更判定**
   - 若目标坐标已经是期望的方块类型和状态，直接判定为“无需变更”，返回成功但不发送任何指令。
   - 这节省了网络往返，也避免了“假装成功”的语义混乱。

3. **执行放置动作**
   - 发出放置/替换指令。注意：此步骤为“发出指令”而非“完成修改”，因为 MC 服务端可能因网络、tick 延迟或并发修改导致最终结果不确定。

4. **执行后确认（闭环验证）**
   - harness**必须**重新读取目标坐标的方块状态，与预期比较。
   - 若一致，标记为成功；若不一致，进入兜底流程（见第七节）。
   - 此步骤是 MC 场景下的强制要求，体现了“环境不可靠则更要确认”的设计精神。
   - 不是要求LLM每次使用编辑工具后又使用读取工具再读一次，而是harness层面校验，有问题再返回叫LLM改。

## 六、读取方块（读操作）的设计

- **批量读取优先**：支持给一个区域（bounding box）一次性获取所有方块信息，避免逐点调用。
- **输入/输出归一化**：
  - 统一方块 ID 命名空间（如全部转换为 `minecraft:xxx`）。
  - 统一坐标表示（世界坐标或相对坐标在 schema 中明确并一致）。
  - 消除表示形式的差异，防止因格式不一致而误判状态匹配。
- **显式的“未知”状态**：
  - 区块未加载、超出渲染距离等情况，返回明确的 `unknown/unloaded`，不得返回看似合法的默认值（如空气）。
  - 下游所有校验逻辑依赖“读到的状态为真”这一假设，伪造默认值会破坏可靠性。

---

## 七、并发互斥设计

- **互斥 key**：按**坐标**或**所在区块**作为锁 key。针对同一 key 的读-判断-写序列必须串行排队，不同 key 之间可并行。
- **作用范围**：该队列仅保证 Agent 自身发起的操作不会在并发时自相冲突，**无法防止外部世界（其他玩家、生物、红石）在两次读取之间的变化**——这正是“执行后确认”步骤不可省略的根本原因。
- **取消/超时处理**：
  - 网络请求超时或客户端断线时，不能立即认定操作失败并释放锁。
  - 应保持锁定，直到明确拿到“成功/失败/未知”三态之一的确认结果，再解锁并返回。
  - 每次异步等待后需手动检查取消状态，而非在事件回调中草率 reject。

---

## 八、兜底策略（Fallback）分层设计

按失败发生的阶段分层处理：

1. **前置条件不满足（执行前）**
   - 尝试补救，尽量兜底
   - 补救仍失败则直接返回结构化错误，不再重试（因为重复同样动作不会改变结果）。

2. **精确匹配 → 宽松匹配降级**
   - 若目标坐标当前方块与前置断言不完全一致（例如状态变体不同），可启用“宽松匹配”模式。
   - 一旦触发宽松匹配，必须在返回结果中明确标注“本次为模糊匹配命中”，不能静默处理。
   - 宽松匹配的具体规则（如忽略状态、忽略变种）需在工具契约中明确定义。

3. **执行后状态不符合预期（MC 特有）**
   - 由于网络不确定性，执行后可能状态未变或变为非预期状态。
   - 处理层级：
     1. 有限次数的“重新确认读取”（可能只是读取时机过早，状态尚未同步）。
     2. 若仍不一致，尝试有限次数的重新执行（可能由于瞬时的阻挡/红石干扰）。
     3. 最终失败则返回明确分类：放置被阻挡、背包已消耗但世界未变化、权限保护区域拒绝等，将决策权交还给上层 Agent。

4. **批量操作的原子性声明**
   - 默认行为：**允许部分成功**，并如实报告每个 Edit 的独立结果（成功/失败/原因）。
   - 可选行为：若调用方明确要求“原子性”，则在任一 Edit 失败时，主动执行补偿性撤销（回滚已成功的操作）。
   - 回滚成本需考虑：撤销已放置的方块往往需要额外的挖掘动作，代价可能高于保留部分成功，因此原子性不作为默认值。

---

## 九、反馈设计（执行结果与预览）

- **结构化反馈**：执行结果返回每个 Edit 的最终状态，包含：
  - 操作是否成功。
  - 如果是宽松匹配命中，注明降级说明。
  - 执行前后的实际方块类型/状态对比。
  - 若失败，具体原因分类及上下文。
- **预览一致性**：如果有可视化预览或模拟执行，预览逻辑必须与真实执行共享同一套校验和匹配代码，确保“预览效果”与“实际效果”一致，避免割裂体验。

---

## 十、总结：设计要点速查

| 设计关注点 | 具体策略 |
|---|---|
| 批量操作 | 单次调用可编辑多个坐标 |
| 前置条件校验 | 每个 Edit 含期望的当前状态作为断言 |
| 输入预处理 | 格式归一化与语义校验严格分层 |
| 空变更处理 | 目标已是期望状态则跳过并上报 |
| 执行后确认 | 强制重新读取，验证生效 |
| 匹配降级 | 精确→宽松，降级须显式标注 |
| 失败兜底 | 分阶段、有限重试、明确分类 |
| 并发控制 | 按坐标/区块队列串行，外部变化不隔离 |
| 原子性 | 默认部分成功，原子性为可选契约 |
| 反馈 | 结构化、可操作，预览与执行同源 |
