# 07 — 完成跨宿主、Add-on 与实际 Minecraft 验收

**What to build:** 验证新的方块查看和独立编辑组在宿主、Add-on、模型 schema、审批、工具审计及实际 Minecraft 场景中形成完整闭环，并达到设计中定义的调用效率和安全指标。

**Blocked by:** 02 — 使用统一 target 完成有界方块查看; 04 — 扩展为一次审批的独立编辑组; 05 — 补齐方块修复建议与多格方块安全语义; 06 — 执行结构化命令回退限制并收敛工具提示.

**Status:** ready-for-agent

- [ ] Python 测试覆盖新模型 schema、预检、审批恢复、幂等、聚合投影、回退限制、审计和多人身份隔离并全部通过。
- [ ] Add-on 测试覆盖点集、box、分组预检、去重、冲突、部分匹配、写后确认、状态未知和多格方块语义并全部通过。
- [ ] 所有受支持 provider 获得相同的新工具 schema，模型不可见旧 `mode`、单点/区域互斥字段和 Harness 内部恢复字段。
- [ ] 样例建房先用一次区域查看取得有界摘要，再用 1 至 2 个主体或墙体编辑组、1 个门窗组和 1 个内饰照明组完成任务。
- [ ] 专用方块能力可用时，样例中不出现 `setblock`、`fill` 或 `clone` 自动回退；多格方块要么完整成功，要么明确报告不支持。
- [ ] 样例总工具调用目标为约 5 至 7 次，模型请求目标为约 3 至 5 次，并记录与原基线的对比结果。
- [ ] 最终模型回复依据聚合结果生成，不把 `partial`、`failed` 或 `unknown` 描述为全部完成。
- [ ] 工具审计顶层状态与实际结构化结果一致，完整证据保持有界，预检、审批、执行和审计中的 `player_name` 全程一致。
- [ ] 配置示例、能力版本说明和桥协议说明与最终行为一致，完整自动化测试与实际 Minecraft 验收结果均有记录。
